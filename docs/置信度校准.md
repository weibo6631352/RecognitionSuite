# 置信度与校准

## “未校准”是什么意思

当前界面中的置信度是模型内部评分。它通常可以帮助排序和定位低可信结果，
但数值没有经过独立真值数据的概率校正。因此，显示 `98%（未校准）` **不表示**
“这段文本有 98% 的概率完全正确”，也不表示“字符准确率为 98%”。正式的 98%
验收结论始终来自冻结真值与识别文本的字符编辑距离，置信度不能替代该结论。

校准的目标是预先定义某个可验证事件，再让预测概率与事件的实际发生频率一致。
例如，把 `0.8` 定义为“该样本达到约定质量门槛的概率”，则大量预测为 `0.8`
的同类样本中应约有 80% 达标。目标也可以是“规范化文本完全正确”，但必须在
校准产物和 UI 中明确写出，不能只写含义不明的“准确概率”。

## 当前两个评分的实际含义

### 语音识别

VoiceEngine 对每个语音段计算所选解码 token 概率的几何平均，来源标识为
`decoder_token_geometric_mean`。RecognitionStudio 再对段分数计算算术均值、
最小值、最大值和段数；整套验收报告按段数加权汇总样本均值。

该分数反映解码器对已选 token 的相对把握，但会受音频质量、文本长度、解码
策略、语言和模型版本影响，尚未建立它与“整段正确”或“样本达标”的频率关系。

### 扫描识别

RecognitionStudio 当前从结果对应的 `*_middle.json` 和 `*_model.json` 中递归
收集字段名为 `score` 或 `confidence`、且位于 `[0,1]` 的数值，再计算算术
均值、最小值、最大值和数量，来源标识为 `scan_intermediate_score`。

这些值可能来自不同识别阶段，甚至包含结构性占位分数，语义并不一致；它们
不是最终 OCR 文本正确概率。要正式校准扫描置信度，应先在 SDK 结果契约中固定
一种语义稳定、可版本化的样本级或文本块级原始分数，不能直接把混合中间分数
当成单一概率。

## 为什么当前冻结集不能用于校准

仓库内置的独立冻结验收集用于验证 98% 指标，不是校准训练集。当前每个任务
只有 8 个样本：语音 8 个样本全部识别正确，没有错误样本；扫描 8 个样本共
563 个真值字符，仅有 1 个编辑错误，而收集到的 50 个扫描中间分数全部为
`1.0`。这些数据既缺少足够的正确/错误对照，也没有覆盖完整分数区间，无法
估计一条稳定、可复现的概率映射。

更重要的是，使用冻结验收集拟合或挑选校准器会让裁判数据参与调参，造成数据
泄漏。即使随后仍在同一验收集上得到漂亮指标，也不能作为独立证明。因此现有
结果应继续标记为“未校准”，不得把验收集反向用作校准数据。

## 公正的独立校准流程

1. **先定义目标。** 分任务、分评分来源声明校准事件，例如“规范化文本完全
   正确”或“样本字符准确率达到 98%”。同时冻结文本规范化、样本聚合和缺失
   结果处理规则。
2. **先分组再推理。** 由独立方按说话人、录制来源、文档来源或模板族分组，
   冻结互不重叠的校准集和最终验收集；近重复样本不得跨集合。最终验收集对
   模型开发者和校准过程保持封存。
3. **只在校准集拟合。** 收集未经修改的原始分数和真值标签。数据应覆盖真实
   场景、主要质量区间以及足够数量的达标和未达标样本；当前的 8 个样本远远
   不够。样本规模应按允许的校准误差和置信区间预先确定，工程起步通常需要
   数百个以上样本，并确保关键分层中同时存在正、负结果。
4. **选择并锁定方法。** 有稳定 logits 时优先评估温度缩放；只有单一分数时，
   可用带正则的逻辑回归（Platt scaling）作为低方差基线；数据充足且关系明显
   非线性时可用保序回归（isotonic regression）。方法与超参数只能在校准集
   内通过预先约定的交叉验证选择，不能查看最终验收结果后再更换。
5. **冻结校准器。** 拟合完成后生成不可变校准产物及 SHA-256，再首次运行最终
   验收集。任何模型、评分定义或规范化规则变化，都必须重新校准并重新验收。
6. **独立检查。** 在未参与拟合的最终集合上同时报告 Brier 分数、ECE、可靠性
   图和每个分箱的样本数；ECE 的分箱方式必须预先声明。建议用分组 bootstrap
   给出置信区间。Brier 越低越好；可靠性图应接近对角线。区分能力指标不能
   代替这些校准检查。

温度缩放、逻辑回归和保序回归只是候选方法，不应预设某一种必然最好。应依据
独立数据上的预先规定指标选择，并保留“未校准”基线用于对照。

## 校准产物与版本绑定

每个校准产物至少应保存以下元数据：

- 校准器 schema、ID、算法、参数、生成时间和工具版本；
- 任务类型、原始评分来源、评分定义、聚合层级和有效输入范围；
- 校准目标、文本规范化、达标阈值和异常/缺失值规则；
- Engine SDK、模型、运行时配置的版本及 SHA-256；
- 校准清单和独立评估清单的 ID、SHA-256、样本数及分层摘要；
- Brier、ECE、分箱边界与计数、可靠性图数据及置信区间；
- 校准产物自身 SHA-256，以及审核者或生成方标识。

应用只能在任务类型、评分来源及定义、模型/SDK 版本、规范化和校准目标都匹配
时使用该映射。绑定条件不匹配、分数越界或元数据不完整时，必须回退为原始
“未校准”分数，不能沿用旧映射或静默外推。

## UI 展示语义

UI 应把实际准确率、原始分数和校准概率分开显示：

- 未加载有效校准器：`原始置信分数 98.84%（未校准，不代表准确率）`；
- 已匹配有效校准器：`预计达标概率 96.2%（目标：样本准确率 ≥ 98%）`，并保留
  可查看的原始分数、校准器 ID 和 SHA-256；
- 不匹配或超出适用范围：显示具体原因，并恢复“未校准”标记。

证据面板应能查看评分来源、聚合方式、校准目标、校准器元数据和独立评估指标。
无论置信度是否已校准，98% 验收页的“通过/不通过/验证无效”都只能由冻结真值
计分和证据完整性决定，不能由置信度阈值决定。
