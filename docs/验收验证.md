# UI 验收验证

RecognitionStudio 的“验收验证”页使用已发布的 ScanEngine / VoiceEngine SDK
串行执行冻结测试集，并在界面内按字符编辑距离计算正式 98% 指标。模型置信度
同时展示，但属于未经校准的辅助诊断信号，不能替代真值评分。

## 清单格式

每份清单只包含一种任务，路径相对于清单所在目录。正式阈值不得低于 `0.98`。

```json
{
  "schema": "RecognitionStudio-Acceptance/1",
  "dataset_id": "VOICE-ACCEPT-2026-01",
  "task_type": "voice",
  "threshold": 0.98,
  "normalization": {
    "remove_whitespace": true,
    "ignore_punctuation": false,
    "case_sensitive": true
  },
  "samples": [
    {
      "id": "voice-001",
      "input": "audio/voice-001.wav",
      "input_sha256": "64 位十六进制 SHA-256",
      "reference_path": "truth/voice-001.txt",
      "reference_sha256": "64 位十六进制 SHA-256"
    }
  ]
}
```

`task_type` 为 `scan` 或 `voice`。每个样本必须提供输入和真值 SHA-256，加载
清单时即校验，防止只冻结清单却在运行前替换媒体或真值。真值可使用
`reference_path`，也可在小型诊断清单中使用 `reference_text`；后者的哈希按其
UTF-8 字节计算。正式清单应使用独立真值文件并整体冻结。

## 计分与完整性

文本先执行 Unicode NFC、换行归一化和首尾空白清理，再按清单选择是否删除
空白、忽略标点或忽略大小写。整套测试集采用微平均：

```text
准确率 = 1 - Σ编辑距离 / Σ真值字符数
```

任何样本缺失、SDK 失败、CUDA OOM 或结果无法读取，都会计入失败样本并使最终
结论成为“验证无效”；界面不会只对成功样本给出“通过”。清单阈值达到、全部
样本完成且无失败时，界面才显示“通过”。

## 证据输出

每次运行建立独立时间戳目录，保存：

- `report.json`：清单 SHA-256、汇总指标、置信度和最终结论；
- 每个样本的 `reference.txt`、`hypothesis.txt`、`sample.json`；
- SDK 返回的扫描结果路径、Excel 路径、`fallback_count` 或语音原始结果 JSON；
- 每个输入文件的 SHA-256。

VoiceEngine 的置信度为所选解码 token 概率的几何平均。ScanEngine 当前展示
`*_middle.json` 与 `*_model.json` 中 `[0,1]` 分数的统计，并明确标记来源和
“未校准”。不同阶段的分数不能解释为实际准确率。
