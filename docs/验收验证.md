# UI 验收验证

RecognitionStudio 的“验收验证”页使用已发布的 ScanEngine / VoiceEngine SDK
串行执行冻结测试集，并在界面内按字符编辑距离计算正式 98% 指标。模型置信度
同时展示，但属于未经校准的辅助诊断信号，不能替代真值评分。

## 仓库内置独立冻结集

仓库已经提供由 Codex 独立生成和标注的两份冻结清单，待测程序没有参与真值
制作：

- 扫描：`testdata/acceptance/codex-independent-2026-09/scan/manifest.json`；
- 语音：`testdata/acceptance/codex-independent-2026-09/voice/manifest.json`。

在 UI 的“验收验证”页选择其中一份 `manifest.json` 即可执行。输入媒体、真值、
生成来源与哈希都随清单存档；详细边界见 `testdata/acceptance/README.md`。

## 清单格式

每份清单只包含一种任务，路径相对于清单所在目录。正式阈值不得低于 `0.98`。

```json
{
  "schema": "RecognitionStudio-Acceptance/1",
  "dataset_id": "VOICE-ACCEPT-2026-01",
  "task_type": "voice",
  "threshold": 0.98,
  "normalization": {
    "remove_whitespace": true,
    "ignore_punctuation": false,
    "case_sensitive": true
  },
  "samples": [
    {
      "id": "voice-001",
      "input": "audio/voice-001.wav",
      "input_sha256": "64 位十六进制 SHA-256",
      "reference_path": "truth/voice-001.txt",
      "reference_sha256": "64 位十六进制 SHA-256"
    }
  ]
}
```

`task_type` 为 `scan` 或 `voice`。每个样本必须提供输入和真值 SHA-256，加载
清单时即校验，防止只冻结清单却在运行前替换媒体或真值。真值可使用
`reference_path`，也可在小型诊断清单中使用 `reference_text`；后者的哈希按其
UTF-8 字节计算。正式清单应使用独立真值文件并整体冻结。

## 计分与完整性

文本先执行 Unicode NFC、换行归一化和首尾空白清理，再按清单选择是否删除
空白、忽略标点或忽略大小写。整套测试集采用微平均：

```text
准确率 = 1 - Σ编辑距离 / Σ真值字符数
```

任何样本缺失、SDK 失败、CUDA OOM 或结果无法读取，都会计入失败样本并使最终
结论成为“验证无效”；界面不会只对成功样本给出“通过”。清单阈值达到、全部
样本完成、证据与汇总报告均成功写入且无失败时，界面才显示“通过”。

## 证据输出

每次运行建立独立时间戳目录，保存：

- `report.json`：清单 SHA-256、汇总指标、置信度和最终结论；
- `SHA256SUMS.txt`：对最终 `report.json` 的独立 SHA-256 锚点；
- 每个样本的 `reference.txt`、`hypothesis.txt`、`sample.json`；
- 语音样本的独立 `raw-result.json` 及 SHA-256；
- SDK 返回的扫描结果路径、Excel 路径、`fallback_count` 或语音原始结果 JSON；
- 输入、识别文本及扫描中间产物的 SHA-256。

验收页下方内嵌证据面板与样本表格联动，可直接查看冻结真值、识别文本、样本
指标、置信度来源、产物路径和 SHA-256；“汇总报告”页签展示本次
`report.json` 及其外部 SHA-256，无需打开目录才能核验。正式验证开始前和结束
后，应用都会用编译进程序的发布基线锚点核对 SDK 清单，并逐项哈希实际部署的
两套 SDK `bin/` 文件；VoiceEngine 合并后的完整 GGUF 通过已锚定的模型清单
单独核对。主程序和扫描工作进程实际从宿主目录加载的 Qt/MSVC DLL 与 Qt 插件
也按 ScanEngine 发布基线核验，并拒绝清单外 DLL。任一模型、DLL、配置或
ScanEngine 的 NVRTC 运行时头文件不匹配，结论只能是“验证无效”。报告同时
记录应用和扫描工作进程的首尾哈希，以发现
运行期间替换。打开证据目录仍作为查看 Excel 等原始文件的补充入口。

`report.json` 内的指标结论只有在同目录 `SHA256SUMS.txt` 存在且重新计算后
完全匹配时才有效；孤立的 `report.json` 不构成“通过”证据。这样即使报告与
校验文件之间发生写入中断，也只能得到“验证无效”，不能留下可独立采信的通过
结论。

VoiceEngine 的置信度为所选解码 token 概率的几何平均。ScanEngine 当前展示
`*_middle.json` 与 `*_model.json` 中 `[0,1]` 分数的统计，并明确标记来源和
“未校准”。不同阶段的分数不能解释为实际准确率。
校准含义、数据隔离和产物绑定要求见 [置信度校准](置信度校准.md)。
