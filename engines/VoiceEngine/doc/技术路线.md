# VoiceEngine 技术路线

## 1. 项目目标

VoiceEngine 是一个运行在 Windows 本地电脑上的中文语音识别桌面程序，主要能力包括：

- 将音频文件或麦克风语音转换为中文文字；
- 尽量保留和生成合理的中文标点；
- 支持普通话、常见中文方言及中英文混合语音；
- 使用本机 NVIDIA RTX 5090 进行 GPU 推理；
- 提供 C++ / Qt 图形界面、稳定 DLL 接口和命令行工具；
- 所有运行组件随程序发布，目标电脑无需安装 Python、CUDA Toolkit、FFmpeg 或其他开发环境；
- 不使用 WSL，不把 CPU 语音识别作为产品路径。

项目采用与 `ScanEngine` 相近的 Windows C++ / Qt 工程组织方式，但将公共核心封装为 DLL。

## 2. 总体原则

1. **GPU 是唯一正式推理路径**
   - 正式模型固定运行在 NVIDIA CUDA 上；
   - 默认设备为 RTX 5090，目标计算能力为 `sm_120`；
   - 模型或 CUDA 初始化失败时明确报错，不静默降级到 CPU 推理；
   - CPU 只负责界面、音频解码、重采样、文件读写、任务调度等轻量工作。

2. **GUI 直接调用 DLL**
   - Qt 主程序直接调用 `VoiceEngineCore.dll`；
   - GUI 不通过反复启动 CLI 完成识别；
   - 模型在进程内常驻显存，避免每次任务重新加载。

3. **GUI 和 CLI 共用同一个核心**
   - `VoiceEngine.exe` 和 `VoiceEngineCli.exe` 都调用 `VoiceEngineCore.dll`；
   - 推理、音频处理和结果格式化只实现一次；
   - CLI 主要用于批处理、自动化、性能测试、诊断和故障复现。

4. **运行包绿色免安装**
   - Qt、MSVC、CUDA 运行库和必要工具随程序部署；
   - 不依赖系统 `PATH`；
   - 模型由项目或安装包预先准备，程序运行时不自动联网下载；
   - 必要的第三方命令行工具可以随包发布，但必须固定版本并放在程序私有目录。

## 3. 总体架构

```text
VoiceEngine.exe（Qt GUI）
          │
          ├──────────────┐
          ▼              ▼
VoiceEngineCore.dll   VoiceEngineCli.exe
          ▲              │
          └──────────────┘
          │
          ├─ 任务队列、进度、取消、日志
          ├─ 音频解码、重采样、静音切分
          ├─ Qwen3-ASR 输出解析及中文格式整理
          └─ llama.cpp / libmtmd / CUDA
                         │
                         ▼
                Qwen3-ASR-1.7B BF16
                         │
                         ▼
                    RTX 5090
```

第一版采用进程内 DLL 推理，以获得最简单的部署结构和最低的数据传递开销。

## 4. 技术选型

### 4.1 操作系统和工具链

| 项目 | 选择 |
|---|---|
| 操作系统 | Windows 11 x64 |
| GUI | C++ / Qt 5.12.9 Widgets |
| 编译器 | Visual Studio 2022 v143 x64 |
| C++ 标准 | C++17，必要时局部使用 C++20 |
| 构建系统 | CMake + CMakePresets.json |
| CUDA | CUDA 12.9 |
| GPU 架构 | `sm_120` |
| CRT | `/MD`，随程序部署 MSVC 运行库 |

第一阶段保持与 `ScanEngine` 相同的 Qt 和 MSVC 主工具链，减少本机环境差异。暂不同时迁移 Qt 6 或新的 MSVC ABI。

### 4.2 主识别模型

主模型选择：

```text
Qwen3-ASR-1.7B
```

使用原则：

- 第一版优先使用 BF16 权重；
- 模型全部放入 RTX 5090 显存；
- 不因兼容低配置电脑而默认换成 0.6B 或低比特模型；
- 经过精度对照后，可以额外提供 Q8_0 模型包；
- Q4 等更低比特量化不作为第一版默认方案；
- 输出保留模型生成的中文标点，只做必要的全角、空格和重复标点规范化。

### 4.3 默认推理后端

默认后端：

```text
固定版本的 llama.cpp + libmtmd + CUDA
```

理由：

- 原生 C/C++，适合封装到 DLL；
- 支持 Qwen3-ASR-1.7B 和音频输入；
- 支持 Windows CUDA，可以利用 RTX 5090；
- 不需要 Python、PyTorch、Web 服务或 WSL；
- 可以固定源码提交版本，和项目一起编译、测试和发布；
- 后续升级推理框架时不影响 DLL 公共接口。

当前 Qwen3-ASR 音频支持仍较新，因此必须使用固定且经过验证的 llama.cpp 提交版本，不直接追随每日更新。正式发布前通过中文测试集验证准确率、标点和长时间稳定性。

## 5. DLL 设计

DLL 名称：

```text
VoiceEngineCore.dll
```

DLL 使用稳定 C ABI，对外不导出 `QString`、`std::string`、STL 容器、C++ 异常或带虚函数的 C++ 类。

公共接口至少包括：

- 查询 API 版本；
- 创建和销毁识别上下文；
- 检查 CUDA 设备；
- 加载和卸载模型；
- 异步提交音频文件；
- 异步提交 PCM 音频数据；
- 获取任务状态和进度；
- 接收临时文本和最终结果；
- 取消任务；
- 获取最后错误信息。

接口约定：

- Windows 文件路径使用 UTF-16；
- 文本和 JSON 使用 UTF-8；
- 所有公共结构体带 `struct_size` 和 API 版本；
- DLL 内分配的内存由 DLL 提供释放函数；
- 所有异常在 DLL 内转换为错误码；
- 回调不直接操作 Qt 控件；
- 推理任务在工作线程执行，Qt 主线程只处理界面事件；
- 同一个模型上下文第一版只允许一个活动推理任务，其他任务进入队列。

## 6. 音频处理与 FFmpeg

### 6.1 音频处理目标

模型输入统一转换为：

```text
16 kHz、单声道、float32 PCM
```

处理流程：

```text
输入文件
  → 格式探测
  → 解码
  → 单声道混合
  → 16 kHz 重采样
  → 静音检测和切片
  → GPU 识别
  → 结果拼接及标点规范化
```

### 6.2 FFmpeg 集成方式

FFmpeg 只以动态库方式集成，以减少自行维护大量音频封装格式的工作量。

#### FFmpeg 动态库

`VoiceEngineCore.dll` 直接链接以下 FFmpeg 共享库：

- `avformat`：探测和解封装音频、视频文件；
- `avcodec`：解码音频流；
- `avutil`：样本格式、通道布局和公共工具；
- `swresample`：转换为 16 kHz、单声道、float32 PCM。

第一版不引入当前用不到的 `avfilter`、`avdevice`、`postproc` 等组件。FFmpeg 接口只封装在 `src/audio/ffmpeg/` 内部，不暴露到 `VoiceEngineCore.dll` 的公共头文件。

使用动态库的原因：

- 音频数据可以在内存中直接交给识别管线；
- 不需要为每个任务创建外部进程；
- 不需要先生成大型临时 PCM 文件；
- 进度、取消、错误信息和日志更容易统一管理；
- 批量处理短音频时延迟更低；
- 仍然可以将 DLL 和运行库一起复制，实现绿色免安装发布。

源码/依赖目录建议：

```text
third_party/windows-x64/ffmpeg/
├─ include/
│  ├─ libavcodec/
│  ├─ libavformat/
│  ├─ libavutil/
│  └─ libswresample/
├─ lib/
│  ├─ avcodec.lib
│  ├─ avformat.lib
│  ├─ avutil.lib
│  └─ swresample.lib
├─ bin/
│  ├─ avcodec-*.dll
│  ├─ avformat-*.dll
│  ├─ avutil-*.dll
│  └─ swresample-*.dll
├─ LICENSE.txt
├─ VERSION.txt
├─ SOURCE_URL.txt
└─ SHA256SUMS.txt
```

发布时，将必要的 FFmpeg DLL 放到程序私有运行目录：

```text
bin/runtimes/ffmpeg/
├─ avcodec-*.dll
├─ avformat-*.dll
├─ avutil-*.dll
├─ swresample-*.dll
└─ LICENSE.txt
```

程序启动时通过 Windows 的安全 DLL 搜索接口添加该私有目录，不把它写入系统 `PATH`，也不修改用户环境变量。

#### 版本与许可证要求

- 固定 FFmpeg 主版本、完整版本号和构建来源；
- 校验头文件、导入库和 DLL 的 SHA-256；
- 头文件、`.lib` 和 `.dll` 必须来自同一套构建；
- 发布时保留 FFmpeg 许可证、第三方声明和源码获取说明；
- 默认选择符合项目发布要求的 LGPL 共享库构建；
- 不启用当前产品不需要的 GPL 或不可再分发组件；
- 升级 FFmpeg 时先通过音频格式、中文路径、长音频、内存泄漏和 ABI 回归测试。

对于 WAV/PCM，可以选择内置轻量读取器；MP3、AAC、M4A、FLAC、Opus 以及视频文件中的音轨由 FFmpeg 动态库解码。解码失败时直接返回清晰的格式或解码错误。

## 7. 长音频和准实时识别

### 7.1 长音频

长音频不直接一次性送入模型。第一版按静音位置切分，建议目标片段长度约 30～60 秒，最大不超过 120 秒。

切片策略需要：

- 保留少量前后重叠，避免切断词语；
- 记录每段原始时间偏移；
- 单段失败时可以重试，不重跑整个文件；
- 合并时消除重叠文本；
- 每完成一个片段更新 GUI 进度；
- 用户取消后停止后续片段，并安全结束当前 GPU 调用。

### 7.2 麦克风识别

第一版采用准实时方案：

- WASAPI 或 Qt 音频接口持续采集；
- 按静音或短时间窗口形成语音片段；
- 片段提交到 GPU；
- GUI 显示临时识别结果；
- 句段结束后用较完整上下文重新确认最终文本。

该方案不依赖 vLLM，也不使用 WSL。后续只有在原生推理后端提供稳定的真正流式接口后，才升级为模型原生流式识别。

## 8. CLI 设计

CLI 名称：

```text
VoiceEngineCli.exe
```

建议命令：

```text
VoiceEngineCli info
VoiceEngineCli transcribe --input AUDIO --output RESULT
VoiceEngineCli transcribe-dir --input DIR --output DIR
VoiceEngineCli benchmark --dataset DIR
VoiceEngineCli verify-runtime
```

约定：

- stdout 输出最终文本或 JSON；
- stderr 输出日志、进度和诊断信息；
- 为参数错误、音频错误、模型错误、CUDA 错误和任务取消定义不同退出码；
- 支持 TXT、JSON 和 JSONL；
- GUI 不以启动 CLI 的方式执行普通识别任务。

## 11. 开发阶段

### 阶段一：原生后端验证

- 固定 llama.cpp 提交版本；
- 在 RTX 5090 上编译 CUDA `sm_120`；
- 加载 Qwen3-ASR-1.7B BF16；
- 完成 WAV 文件转写；
- 验证中文、标点、中英文混合和长音频切片；
- 建立固定中文测试集，记录 CER、标点 F1、速度和显存占用。

### 阶段二：DLL 和 CLI

- 定义稳定 C ABI；
- 实现模型生命周期、异步任务、进度和取消；
- 实现 `VoiceEngineCli.exe`；
- 实现 JSON 结果格式；
- 增加 CUDA、模型和 FFmpeg 自检。

### 阶段三：Qt GUI

- 文件选择和拖放；
- 模型加载状态；
- 识别队列和进度；
- 临时文本与最终文本展示；
- 结果保存和复制；
- 任务取消和错误提示。

### 阶段四：音频格式和长音频

- 集成 FFmpeg 动态库；
- 支持常用音频和视频文件中的音轨；
- 实现静音切分、重叠合并和失败重试；
- 增加长时间稳定性测试。

### 阶段五：麦克风与可选能力

- 麦克风准实时识别；
- 可选时间戳和字幕导出；
- 评估 Q8_0 模型包；
- 完善长时间录音和批量任务体验。

## 12. 验收标准

正式版本至少满足：

- 明确识别到 RTX 5090，并确认主要模型层运行在 CUDA；
- CUDA 初始化失败时停止识别并报告原因，不转为 CPU ASR；
- Qwen3-ASR-1.7B BF16 能稳定加载和卸载；
- 中文路径、空格路径和超长路径经过测试；
- 常用音频格式通过随包 FFmpeg 正常转换；
- 连续批量识别至少 2 小时不崩溃、不持续增加显存或内存；
- 长音频切片不会产生明显重复或漏段；
- GUI 识别期间保持响应，可以取消任务；
- CLI 和 GUI 对同一输入产生一致结果；
- 固定中文测试集的 CER、标点 F1 和专有名词结果达到项目验收门槛；
- 发布目录复制到另一台仅安装 NVIDIA 驱动的 Windows 电脑后可以直接运行；
- 所有第三方库、工具和模型都带有版本、来源、许可证及校验记录。

## 13. 当前结论

VoiceEngine 第一版采用以下正式路线：

```text
Windows 11 x64
  + C++ / Qt 5.12.9
  + VoiceEngineCore.dll
  + llama.cpp / libmtmd
  + Qwen3-ASR-1.7B BF16
  + CUDA 12.9 / RTX 5090 / sm_120
  + 随包发布的 FFmpeg 动态库
```

GUI 直接异步调用 DLL；CLI 调用同一个 DLL。正式产品不提供 CPU ASR 降级路径，不使用 WSL，不要求用户安装 Python、CUDA Toolkit 或 FFmpeg。
